# VLM 模块开发日志（2026-09-16）

## 今日目标

将 VLM 的职责明确为：接收目标描述和相机观测，识别目标并输出目标在 `map` 坐标系下的三维坐标。避障、可达点选择、路径规划和机器人运动控制不属于本模块。

## 已完成内容

1. 保留了原始 `vlm` 代码，新增独立目录 `semantic_target_locator` 实现新版目标定位逻辑。
2. 定义了稳定的输入输出接口，可接收：
   - 目标描述，例如 `red chair`；
   - 基础检测类别，例如 `chair`；
   - RGB 图像；
   - 与 RGB 对齐的深度图；
   - 相机内参 `CameraInfo`；
   - 图像时间戳和 `map <- camera` TF。
3. 实现了目标定位流程：
   - 视觉检测器找出所有基础类别候选；
   - CLIP 根据完整目标描述选择最匹配的候选；
   - 从目标框内提取深度并反投影到相机三维坐标；
   - 使用 TF 转换为 `map` 坐标；
   - 使用多帧观测进行融合，稳定后输出 `TARGET_LOCKED`。
4. 实现了 ROS1 预留接口：
   - 输入话题：RGB、对齐深度、CameraInfo、目标查询；
   - TF：查询图像时刻的 `map <- camera` 变换；
   - 输出话题：`/semantic/target_status`。
5. 输出只包含目标定位结果，不包含障碍物坐标、导航终点、导航结果或速度指令。

## 当前输出效果

当目标被稳定识别后，新版 VLM 可以输出如下结果：

```json
{
  "status": "TARGET_LOCKED",
  "target": {
    "label": "red chair",
    "frame_id": "map",
    "position": {
      "x": 2.73,
      "y": 3.00,
      "z": 0.42
    },
    "confidence": 0.89,
    "observation_count": 3,
    "position_spread_m": 0.08
  }
}
```

其中 `position` 是目标物体的位置，不是机器人最终应到达的导航终点。导航模块需要根据该位置和 costmap 另外计算安全可达点。

## 验证情况

- 使用包含红色、蓝色和灰色三把椅子的测试图，输入目标 `red chair`。
- GroundingDINO 检测到三把椅子，CLIP 正确选择红色椅子。
- 使用模拟的对齐深度和 `map <- camera` TF，完整链路能够输出 `map` 坐标。
- 三项定位核心单元测试全部通过：正常锁定目标、无检测时不生成假坐标、TF 缺失时正确报告错误。

注意：视觉识别使用了真实模型，但本次三维深度和 TF 是模拟数据，因此只验证了接口和计算链路，输出坐标不是机器人实测坐标。

## 当前完成度

新版 VLM 已完成“目标识别 + RGB-D 三维定位 + map 坐标输出”的核心代码和 ROS 接口预留，可以作为后续接入真实机器人的基础版本。

目前仍需完成：

1. 接入真实机器人的 RGB-D、CameraInfo 和 TF 话题，并使用 rosbag 或机器人进行验证。
2. 增加中文目标解析，例如将“红色的椅子”转换为 `target_text=red chair`、`base_class=chair`。
3. 改进目标框内的前景深度提取，避免椅子空隙中的背景深度影响坐标；后续可加入分割掩膜或深度聚类。
4. 根据实际工程补充 catkin 包、launch 文件以及最终的 ROS 消息类型。
5. 与上层搜索状态机和下游导航模块完成联调。

## 职责边界

```text
新版 VLM：目标文本 + RGB-D + TF -> 目标 map 坐标
导航模块：目标 map 坐标 + costmap -> 安全终点、规划与避障
任务控制模块：控制机器人旋转搜索，并协调 VLM 与导航状态
```

## 轻量模式补充

为适配内存有限、目标类型固定的单机环境，新增 `ros_lite_node.py`：

- 保留 YOLO 基础类别检测；
- 用 HSV 颜色像素比例替代 CLIP；
- 支持常见中英文颜色和物体名称；
- 无颜色描述时直接选择检测置信度最高的候选；
- 默认将视觉处理限制为 2 Hz，并丢弃过期帧；
- 与通用模式共用深度、TF、多帧融合和目标坐标输出。

使用三把不同颜色椅子的测试图验证后，轻量模式正确选择红色椅子，且测试过程中
未加载 CLIP。轻量模式的详细说明见 `LITE_MODE.md`。
